# FlightScnr desktop simulator (Windows)

Runs the real FlightScnr firmware on a Windows PC, showing the Waveshare
ESP32-P4-WIFI6-Touch-LCD-4C's round 720×720 screen in a window. It's for working on
the UI and data features without the board.

## What's real and what's faked

**Real** (the same source files as the device build):
- `main.cpp`, every screen in `src/ui/`, and the data services: adsb.fi, Open-Meteo / Tomorrow.io weather, the timezone lookup, adsbdb routes, Planespotters photos, airline logos, the route cache and settings
- the P4 screen driver (`src/hardware/p4_dsi_panel.cpp`) and the GT9271 touch driver (`src/hardware/input_p4.cpp`)

**Faked underneath** (`sim/shim/` headers, `sim/src/` code):

| On the device | In the simulator |
| --- | --- |
| MIPI-DSI panel framebuffer in PSRAM | a heap buffer drawn in an SDL window, with a round bezel |
| GT9271 touch on I2C | a fake GT9271 on the fake I2C bus; the mouse is the finger |
| Wi-Fi via the ESP32-C6, TLS via mbedTLS | the PC's network; HTTPS through Windows WinHTTP |
| NVS Preferences | `sim_data/nvs.txt` |
| LittleFS | `sim_data/littlefs/` |
| FreeRTOS tasks, semaphores, esp_timer | `std::thread`, a mutex and condition variable |
| Backlight PWM (GPIO 26) | window brightness |
| ES8311 codec + speaker (I2S) | SDL audio on the PC's default output |

**Left out:** the Wi-Fi setup portal (`wifi_setup.cpp`), the settings web page
(`settings_web.cpp`) and OTA (`ota_github.cpp`) are stubbed in `sim/src/sim_stubs.cpp`.
Set the radar center with `--lat` / `--lon`. Other settings live in `sim_data/nvs.txt`.

**What it can't tell you:** whether the real panel init, touch chip, ESP-Hosted Wi-Fi,
TLS memory limits or timing work on the hardware. The local clock uses the PC's time
zone. The simulator reports a healthy heap, so the firmware's low-memory recovery paths
never trigger. Those all still need the board.

## Setup (once)

```powershell
winget install BrechtSanders.WinLibs.POSIX.UCRT   # MinGW-w64 GCC
```

The first build downloads SDL2 2.32.10 (the official MinGW dev package) into
`sim/third_party/`, which is git-ignored.

## Run

```powershell
.\sim\run-sim.ps1 -Lat 27.9755 -Lon -82.5332     # build + run, centered on TPA
.\sim\run-sim.ps1 -NoBuild                       # run the last build, last location
```

or `pio run -e sim` and then `.pio\build\sim\program.exe --lat … --lon …`.

- Click = tap. Drag = swipe (the same 140 px threshold as the device).
- **F12** saves a PNG screenshot to `sim_data/`. **Esc** quits.
- `--scale 0.8` makes the window smaller. Touch coordinates still map to the 720×720 panel.

- **Mouse wheel** = two-finger pinch at the cursor: up spreads (zoom in), down squeezes.

### Alert sounds

The 4C plays a short chime through its speaker when an aircraft alert fires. The
simulator plays the same chimes (same synthesizer, `src/hardware/chime_synth.cpp`)
through the PC's speakers via SDL audio.

- **F1–F6** play the tracked (watch list), military, helicopter, private, overhead and
  emergency chimes at the current volume.
- Settings page 3: **Alert Sound** on/off and **Chime Volume** A–E (both play a preview).
- `--chime SEC:NAME` plays one from a script (`tracked`, `military`, `helicopter`,
  `private`, `overhead`, `emergency`, `click`, `rocket`, `satellite`). The last two
  are the sky-events chimes (rocket launch, ISS pass).
- `program.exe --dump-chimes DIR` writes every chime as `chime-<name>.wav` and exits.
- If Windows has no audio output, the simulator runs silently.

### Map under the radar

On the device, the basemap is generated by the browser on the settings web page. The
simulator doesn't have that page, so `tools/sim_bake_basemap.py` does the same bake:
same tiles, zoom, projection, rotation and color adjustments. It writes
`sim_data/littlefs/basemap.jpg` plus the map metadata.

```powershell
.\sim\run-sim.ps1 -NoBuild -Map vfr                       # FAA VFR chart (US only, no key)
.\sim\run-sim.ps1 -NoBuild -Map dark -CartoKey <key>      # CARTO dark / light / voyager
.\sim\run-sim.ps1 -NoBuild -Map vfr -MapMiles 10          # bake a specific range
.\sim\run-sim.ps1 -NoBuild -Map off
```

- CARTO styles need a free key from <https://carto.com/basemaps/apikey>. Without one,
  every tile comes back as an "API KEY REQUIRED" placeholder.
- The map covers the current range, or `-MapMiles`. Zooming in is fine, though it gets
  softer. Zooming out past the baked range, moving the center, or changing Facing
  hides the map until you bake again, just like on the device.
- The launcher closes a running simulator first, because the simulator rewrites
  `nvs.txt` while it runs.

### Scripted runs (UI checks without clicking)

```powershell
.\sim\run-sim.ps1 -NoBuild -Extra '--tap','8:360:677','--shot','20','--tap','34:360:360','--shot','38','--exit-after','40'
```

- `--tap SEC:X:Y` and `--swipe SEC:X1:Y1:X2:Y2` script a finger, in panel pixels.
- `--shot SEC` saves `sim_data/shot-<SEC>s.png`.
- `--exit-after SEC` closes the simulator.
- `--hidden` runs without a visible window (screenshots still work), so a stray
  click can't land on a scripted test. Real mouse presses are logged as
  `[sim] mouse down X,Y`.
- `--data DIR` uses a different settings/cache folder.

- `--offline` makes Wi-Fi report disconnected and every HTTP request fail, for the
  whole run (or set `FLIGHTSCNR_SIM_OFFLINE=1`).
- `--wifi-down A[:B]` drops Wi-Fi from A to B seconds. Leave out B to keep it down.
- `--feed-down A[:B]` keeps Wi-Fi up but fails every HTTP request from A to B seconds.
  Use these to check the radar's "No Wi-Fi" and "Flight data offline" badges.

- `--sky-fake-launch SEC:MIN` adds a fake Falcon 9 launch (Go, SLC-40) at SEC seconds,
  with liftoff MIN minutes later. `9.2` shows the "Look east" banner and plays the
  T-10 chime right away; `0.2` shows liftoff. More than 10 shows the plain countdown.
- `--sky-fake-iss SEC:MIN` adds a fake ISS pass (NW to SE, 58 deg high, 6 min) starting
  MIN minutes after SEC. `1.5` gives the 2-minute warning and chime; `0` is a pass in
  progress, with the ISS marker on the radar edge.
  Tap the top banner (around 360,95) to open the launch / pass details.

All of these can be repeated. Example: tap the disclaimer's Accept at 8 s, screenshot
the radar at 20 s, tap the middle at 34 s, screenshot at 38 s.
